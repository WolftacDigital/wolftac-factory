# PowerShell delivery test contracts

Use for factory builds that change PowerShell notification adapters.

- Execute the real script with a synthetic command shim and explicit scratch input paths. Override LOCALAPPDATA in the child so executable discovery cannot accidentally select the live installation; never let a bad-profile test fall through to a real send.
- End a wrapper that invokes another `.ps1` with `exit $LASTEXITCODE`. Otherwise the wrapper process can return zero after the script returned a failure code.
- Capture positional `$args` values into named variables before using them inside `Where-Object` or other scriptblocks; each scriptblock has its own automatic `$args`, so a fake CLI can silently lose the target ID or throw under StrictMode. Prove the shim's success path as well as fail/noop modes.
- Check every suite reached by the full test-discovery command against the issue's explicit execution restrictions before running it, including newly merged test modules. Do not limit this inspection to named legacy suites: a narrow exception for two harnesses does not authorize another module's non-DryRun transition tests merely because they use scratch outboxes. Request an explicit fixture-only exception on the issue before invocation; never discover the prohibited path only after a green full-suite run.
- Under StrictMode, read optional properties through `$Object.PSObject.Properties[$Name]` and check for null. Enumerating `.Properties.Name` can throw for an empty JSON object.
- Compare timestamp instants, not JSON spellings, when proving a failed delivery does not advance a timestamp. PowerShell round-trips can omit trailing fractional zeros on another platform. Keep byte comparisons for genuine no-write assertions.
- Test pending sends across multiple failed ticks and a health transition. One failed-send retry test alone misses a lost recovery when observed state advances before delivery succeeds. Cover failed recoveries, same-state duplicate suppression, independent concerns and skipped checks.
- Classify CLI-shim assertions as synthetic adapter evidence. They prove argv, files, response parsing and state, not bot identity, permissions, real channel delivery or scheduled-account profile resolution. Never impersonate another profile to close live acceptance.
- Set TMPDIR explicitly to the active profile's scratch root in each test invocation when wrappers or execution kernels may not inherit the terminal environment. Do not assume separate tool kernels share environment state.
- Inspect legacy PowerShell regression harnesses before trusting their hermetic label. A scratch CronDir and fake process token do not isolate a default EnvFile or newer expiry checks. Run unchanged harnesses through an external command shim that supplies scratch EnvFile/PolicyPath, isolates profile variables, and blocks Invoke-RestMethod or uses the supported scratch outbox. Report the wrapper as fixture proof, not a literal unwrapped pass.
- In a PowerShell command shim called from another script scope, keep executable/wrapper handles in explicitly named global variables or a closure. Resolve one executable (on Windows, Join-Path $PSHOME 'pwsh.exe'); Get-Command can return multiple applications and $script: variables resolve to the calling script's scope.
